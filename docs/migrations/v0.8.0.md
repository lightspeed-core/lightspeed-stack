## Context windows for conversation compaction

In v0.8.0, the context window that conversation compaction uses for a model
is set as `metadata.context_window` on the model's
`inference.providers[].allowed_models` entry. The top-level
`inference.context_windows` map is deprecated. It is still accepted, applies
to a model whose entry sets no window, and logs a startup warning.

| v0.7.x | v0.8.0 |
|---|---|
| `inference.context_windows["<provider id>/<model name>"]` | `metadata.context_window` on the `allowed_models` entry named `<model name>` of the `inference.providers` entry with id `<provider id>` |
| A model missing from the map never compacts | The window is looked up in the model data bundled with the service, otherwise 128,000 tokens is assumed |

Move a window only for a provider that `lightspeed-stack.yaml` already
declares under `inference.providers`, and keep the other windows in
`inference.context_windows` for now. An entry added only to carry a window
changes the OGX configuration:

* Adding `inference.providers` to a file with no other synthesis input
  (`vector_store.providers`, an `ogx.config` block) makes it a unified
  synthesis input. Where the OGX server's run configuration is generated from
  the same file (the OGX image entrypoint, `docker-compose.yaml`, the Prow
  manifests), the entrypoint then synthesizes the run configuration from the
  default baseline instead of enriching the mounted `run.yaml`.
* Wherever the OGX configuration is synthesized from the file (unified
  library mode, and the entrypoint above), the entry replaces the provider of
  the same id that comes from `ogx.config.profile` or the baseline. Only its
  `api_key_env`, `extra` and `allowed_models` reach OGX; a typed `config:`
  block is not emitted yet, so settings of the replaced provider such as
  `base_url` or `api_version` are lost. Its `allowed_models` also becomes the
  provider's allow-list, which hides every model it does not list.

**Before (v0.7.x):**

```yaml
inference:
  context_windows:
    rhaiis/granite-3.3-8b-instruct: 131072
```

**After (v0.8.0)**, in the `allowed_models` of the provider's existing entry:

```yaml
inference:
  providers:
    - type: vllm
      id: rhaiis
      # ... the entry's other settings, unchanged ...
      allowed_models:
        - provider_model_id: granite-3.3-8b-instruct
          metadata:
            context_window: 131072
```

A key of the map splits at its first `/`: the part before is the provider
`id` (which defaults to `type`), the rest is the model `name` (which defaults
to `provider_model_id`). A legacy two-file configuration
(`ogx.library_client_config_path`) cannot declare `inference.providers`;
migrate it to the unified `lightspeed-stack.yaml` first.

With compaction enabled, a model that has no configured window now compacts
at `threshold_ratio` of the window found for it instead of never. Set
`metadata.context_window` for self-hosted models whose window is smaller than
128,000 tokens. See the
[conversation compaction guide](../user_doc/conversation_compaction.md#context-window)
for the full resolution order.

## `GET /a2a` removed

In v0.8.0, the `GET /a2a` route is gone. It never ran an A2A operation: the
request was forwarded to the A2A SDK application, whose JSON-RPC route accepts
POST only, and came back as 405 Method Not Allowed. No working call is lost.

| v0.7.x | v0.8.0 |
|---|---|
| `GET /a2a` with accepted credentials: 405, `text/plain`, `Allow: POST` | 405, `application/json` (`{"detail":"Method Not Allowed"}`), `Allow: POST` |
| `GET /a2a` without accepted credentials or the `a2a_jsonrpc` action: 401 or 403 | 405 as above; the router answers before authentication runs |
| `GET /a2a` with no agent card configured: 500 | 405 as above |
| `operationId` `handle_a2a_jsonrpc_a2a_get` in the OpenAPI document | Removed |

Use `POST /a2a` for JSON-RPC calls, and `GET /.well-known/agent.json` or
`GET /.well-known/agent-card.json` to fetch the agent card.
